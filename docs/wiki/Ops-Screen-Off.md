# 息屏与 7x24 运维

## 为什么显示器不能"关电源/拔线"

Windows 把显示器消失当作**显示拓扑变化** → 分辨率重排 → 微信(Qt)窗口错位、
合成输入落点全错,甚至界面锁死(用户实测:没显示屏微信就锁)。

所以鹊桥的息屏 = **系统级关背光**(SC_MONITORPOWER),显示器仍在线:

- 分辨率不变 → 微信窗口坐标不变 → 自动化照常;
- GPU 照常渲染 → 屏幕 BitBlt 截图/OCR 不受影响;
- RDP 随时可连进来查看(远程桌面是独立虚拟显示)。

**否决黑色遮罩窗口**:置顶黑窗与 `restore_and_focus` 置前微信存在 z-order
竞争,且不省电、不防误碰。仅保留为 `mode="overlay"` 的 fallback,默认不用。

## 三层防护

1. **保黑看门狗**:每 6 秒重新压黑一次(防 RDP 接入/杂散输入唤醒背光);
2. **物理输入吞没**:息屏期间低级钩子吞掉人类的键鼠事件(除 `ESC` 与
   `Ctrl+Alt+O`);带 `LLKHF_INJECTED` 标记的**合成**事件(宿主自动化)全部放行
   → 机器完全交给宿主,又不会误碰;
3. **广播超时**:`SC_MONITORPOWER` 用 `SendMessageTimeoutW` 发送,挂起窗口
   不会拖死看门狗线程。

## RDP 断开自愈

远程桌面关闭后会话进入 `WTSDisconnected`/锁屏 → 合成输入失效(发送必失败)。
鹊桥的处理:

- 启动即检测管理员权限,非管理员自动 UAC 提权(`--no-admin` 可跳过);
- 每 5 秒巡检:仅在会话**已断开/锁屏**时执行 `tscon <sid> /dest:console`
  挂回本机控制台(活跃会话绝不打扰);
- **每次发送前**还会调 `ensure_sendable_session()`:不可交互则先自愈再发,
  消除"保活循环还没轮到"的失败窗口。

日志里出现 `微信窗口未能置前: foreground=None` = 桌面无前台(典型的 RDP
断开状态),程序按设计拒绝盲发并告警 —— 不是故障,是守卫在工作。

## 长跑性能设计

- 日志按天滚动,保留 30 天(防单文件无限膨胀);
- 操作队列:执行超时 180s 与排队预算 1800s 分离(避免级联重试风暴);
- 会话指纹缓存 FIFO 上限 800/群(内存有界);
- 消息库 SQLite WAL:后台翻消息不影响写入;`busy_timeout` 5s;
- 截图走屏幕 BitBlt(不再对隐藏窗口 PrintWindow,避免拖死微信渲染管线)。
