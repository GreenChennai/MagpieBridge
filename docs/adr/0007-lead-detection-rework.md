# ADR-0007: 线索检测重构——标签污染、虚拟列表懒加载与显示截断名

日期:2026-09-08
状态:已接受(现场验证:两条补发线索经全部修复点送达测试群)

## 背景

三起现场事故:
1. 客户"洋崽仔"被识别为"**广告源**"入库并转发;
2. 抖音来客聊天列表(rc-virtual-list 虚拟列表)未滚动到的会话**没有头像/昵称
   DOM**,必须滚动下去再滚回来才加载;
3. 两条新线索(L-0217/0218)转发全部 failed。

## 根因(grill)

- **名字误判**:昵称未渲染时,消息窗口标题退化为 `"广告源已留资convXXX"`
  (纯标签串)。`titleName` 的正则 `^(.{1,24}?)(?:广告源|已留资|…)` 以 lazy
  匹配吃掉"广告源"当昵称,且 `nameIsFallback=false` → **绕过**了整套
  "昵称未就绪→刷新重试→兜底名"保护。
- **懒加载缺失**:检测器假定列表条目 DOM 常驻,虚拟列表滚动窗口外的会话
  提取不到任何信息。
- **转发 failed**:与 ADR-0006 同源(挂回控制台后的无前台窗口期置前失败),
  外加新发现:**微信列表把「测试的佛山投流工作群」渲染成尾部
  「佛山投流工作群」**(相似度 0.824 < 0.85 被守卫拒绝——守卫行为正确,
  是匹配规则缺一条"显示截断"口径)。

## 决策

### 浏览器扩展(content.js, v3.0.1)

1. **`sanitizeName()`**:空/正在输入/等于标签词/仅由标签词组成 → "昵称未就绪";
   `itemName`/`titleName` 全部过净化;
2. **`titleName` 加固**:标题以标签词开头(无昵称前缀)→ 直接返回 '';
3. **`refreshListScroll()`**:找到 `rc-virtual-list-holder`,滚动到底→滚回顶,
   强制 React 挂载全部条目(用户实测经验固化);
4. **`detectLeadsInner` 预刷新**:存在"有线索标记/未读但昵称未就绪"条目时
   先滚动刷新(60s 防抖)再重扫;
5. **fallback 管线升级**:先滚动刷新(attempt 1)→ 无效才整页 reload
   (attempt 2)→ 仍无效用兜底名转发(绝不丢线索);
6. `openAndExtract.waitName` 同时等待列表项昵称与窗口标题昵称。

### 宿主(target_guard)

`name_matches` 新增**显示截断兜底**:候选是目标的尾部、长度 ≥6 → 同一会话;
歧义由 `find_unique` 唯一性检查拒绝(如列表另有独立的"佛山投流工作群"短群,
双命中自动拒发)。方向性拒绝/短名规则不变。

### 旧实例热修(plugins/hotfix_foreground.py v1.2)

monkey-patch 三处(不重启提权实例):`WindowManager._force_foreground` /
`restore_and_focus`(ADR-0006 置前备选链+45s 等待)、`target_guard.name_matches`
与 `wechat_adapter_4x.name_matches`(截断兜底;后者是模块级 from-import,
必须 patch 模块绑定)。新 exe 自带正式修复,热补丁幂等共存。

## 否决

- 放宽相似度阈值到 0.82:会让"广州投流工作群"类的近名群进入危险区间;
- 提取前强制点击每个会话触发昵称渲染:动作量过大,风控风险高;
- name_matches 只 patch ocr 单点:from-import 绑定分散,必须逐绑定点覆盖
  (正式修复改函数本体后此问题消失)。

## 验证

- 影月(L-0224)、洋崽仔(L-0225)补发 → 三步(图片卡片/文字/@提醒)全部
  送达"测试的佛山投流工作群",进入待受理跟踪;
- 日志确认截断兜底命中:`列表显示 '佛山投流工作群' ≙ 目标 '测试的佛山投流工作群'`;
- 单测 50/50(新增尾部截断 3 例)。
