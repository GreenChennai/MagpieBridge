# ADR-0009: emoji 昵称、假"待受理"与 RDP 切换后的标题 OCR 缺字

日期:2026-09-09 晚
状态:已接受(现场复现 → 修复;emoji 与标题待微信恢复后实测)

## 三个现场问题与根因

### 1. 客户昵称是 emoji("😂")→ 线索名变成"客户0649"

抖音来客页面把昵称里的 **emoji 渲染成 `<img>`**(非文本节点),
`textContent` 提取不到 → 纯 emoji 昵称提取为空 → 走兜底名
"客户+电话尾4位"(不丢线索的保底,但名字错)。

**修复**:content.js 新增 `deepText()` 深度文本提取——文本节点照收,
`IMG` 节点改取 `alt`/`aria-label`(平台会把 emoji 字符放 alt);
`itemName`/`windowTitle` 全部切换到 deepText。

### 2. "软件显示发出去了,实际没有"

两层问题:
- **逻辑 bug**:三步(图片/联系方式/@)全部 failed 后,插件仍登记
  "跟踪待受理: L-xxx -> @xx"——界面上看起来"已发出等回复"。修复:
  仅 `all_sent` 才进入待受理跟踪;未送达走邮件告警与人工重试。
- **实例半死**:web/OneBot 服务线程死亡但进程存活(reload 无响应、
  端口不通),期间发送必然失败而进程看起来正常。此类状态请直接重启
  实例;长期需加服务健康自检(后续版本)。

### 3. RDP 退出再挂回控制台后,"当前会话"标题缺字/错字

("测试的佛山投流工作群"→"则试的…/试的…")

`_chat_title` 标题裁剪左缘 x=340 过贴:RDP→控制台切换后字体渲染横向
偏移 1-3px,首字"测"只剩半个 → OCR 读成"则"或丢弃。

**修复**:左缘 336 并在首次结果过短(<6 字,疑似截断)时左扩 8px +
2x LANCZOS 放大二次 OCR,取更长的合并结果(截断只会更短,取长无害);
不做子串放行——"佛山投流工作群"是真实存在的另一个群(ADR-0007 教训),
标题校验口径保持严格。

## 部署注意

本轮修复落地于插件/扩展/宿主代码;运行实例 web 线程已死无法热重载,
**需重启实例**(任务管理器结束 MagpieBridge.exe → 重新运行)。浏览器
扩展需在 chrome://extensions 重载 + 刷新来客页。
