# ADR-0010: 自愈去抖与会话感知的息屏输入吞没(RDP 重连被踢修复)

日期:2026-09-10
状态:已接受

## 事故

用户报告:"昨晚更新之后,软件一直拒绝远程桌面访问,一访问就被
『目标机器已经有一个远程桌面链接』踢出来"。

## 根因(两个叠加)

1. **自愈踢人竞态**:用户发起 RDP 连接时,console 会话迁移到 rdp-tcp 的
   几秒窗口内,`WTSConnectState` 短暂为 Disconnected——5 秒巡检撞上即执行
   `tscon /dest:console`,把刚建立的连接拉回控制台 → 用户被踢;再连再踢。
2. **息屏吞输入的新场景生效**:v5.0 修复了旧版 `_screen_off` 恒 False 的
   bug,"物理输入吞没"首次真正生效——但 RDP 键鼠到达机器侧属于**物理输入**
   (无 INJECTED 标记),用户即使重连成功,键鼠也全被吞掉。

## 决策

### 自愈去抖(session_control)

- 触发条件需**连续 3 次巡检命中**(5s 周期 × 3 = 15s):RDP 连接的迁移
  窗口只有几秒,不会连续命中;真断开是持续态,仅延迟 15s 自愈;
- tscon 执行前**再复查一次**探针,桌面恢复则取消;
- `force=True`(手动/Ctrl+Alt+E/发送路径)不受去抖影响。

### 会话感知的吞输入(screen_off)

- `turn_off_display` 时按会话类型决定是否装输入钩子:**远程桌面会话不吞**
  (用户明确息屏但人在远程,键鼠必须可用);本机 console 挂机照常吞;
- 巡检钩子(`update_for_session_state`,挂在 5s 会话保活循环):息屏中
  检测到用户**重连远程桌面**(`WTSWinStationName` 以 RDP 开头)→ 自动
  亮屏退出息屏——用户重连 = 要操作电脑;
- 钩子回调读原子开关 `_swallow_enabled_flag`(巡检随会话类型刷新),
  不在每个输入事件做 WTS 查询。

## 否决

- 巡检撞窗口时"跳过一轮":治标,去抖才覆盖全部瞬时态;
- 吞输入钩子内部做 WTS 会话查询:每个键鼠事件一次查询,开销不可接受。

## 验证

单元测试 5 例(瞬时断开不挂/持续断开去抖后挂/复查取消/force 直通/空判定),
57/57 通过;现场验证:用户断开→连接循环重测。
