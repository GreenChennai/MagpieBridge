# ADR-0006: 断开远程桌面的分层自愈方案

日期:2026-09-08
状态:已接受(现场验证进行中)

## 背景

用户 7x24 挂机:人在别处用 RDP 连机器操作,断开 RDP 后人不在机器前。
已观测到的失败模式:**只要不"盯着"远程桌面,微信发送就失败**。
机器条件:物理显示器常连(公司电脑),进程以管理员运行(自动提权)。

## 失败模式拆解(grill)

| # | 失败模式 | 信号特征 | 原防线 | 缺口 |
|---|---|---|---|---|
| F1 | RDP 客户端关闭 → 会话 WTSDisconnected,注入失效 | state=4 | 5s 巡检 `tscon /dest:console` | 无(需真机验证) |
| F2 | **会话 Active 但桌面无前台**(RDP 最小化/过渡态,`GetForegroundWindow()==0`) | state=0 + fg=0 + 桌面可达 | ❌ 无——巡检只认 Disconnected,永不触发 | **核心洞** |
| F3 | 发送瞬间正好断开/锁屏 | 发送路径探针 | `ensure_sendable_session` 发送前自愈 | 自愈失败后直接放弃 |
| F4 | 挂回控制台后显示拓扑变化(RDP 分辨率 → 物理屏分辨率),微信窗口出屏 | 自愈后 | 无 | 复位窗口位置 |

## 决策(分层防御,全部复用 tscon 单一机制)

- **L0 预防**:启动自动提权 + 防锁屏(关屏保/待机/不活动锁定)——已有;
- **L1 巡检自愈(增强)**:三信号探针 `probe_desktop()`(会话状态/输入桌面/
  前台窗口)+ 纯函数 `should_hang()` 判定。新增 F2 触发:无前台**持续超过
  90 秒宽限期**才挂控制台——短暂 foreground=0 绝不动作,坚决不踢正在使用
  的用户(历史事故:"一连进来就被挂走,只能拼手速关掉");
- **L2 发送路径自愈(增强)**:`_focus_wechat` 置前失败 → 立即
  `ensure_session_active(force=True)` 挂回控制台 + 复位微信窗口位置 +
  **仅重试一次**。安全性论证:置前失败时消息尚未进入输入框,重试不构成
  重复发送;`uncertain` 绝不重试纪律不变;
- **L3 自愈后复位**:挂回控制台后微信窗口 `set_position(0,0,900,600)`,
  对抗分辨率切换;
- **遥测**:自愈动作写日志 + 审计;失败走邮件告警。

## 挂回控制台的行为语义(用户须知)

`tscon <sid> /dest:console` 把会话从 RDP 迁到物理显示器 → 挂回成功即**息屏**
(ADR-0003:关背光 + 保黑 + 吞物理输入,ESC 唤醒)。人不在,机器完全交给宿主;
回公司物理屏前按 ESC 恢复。

## 否决的备选

- **虚拟显示驱动**(IddSampleDriver 等):避免拓扑塌缩,但要装驱动+重启,
  无人值守机器上风险大于收益;
- **阻止 RDP 断开**(改客户端断开行为):治标,远程网络抖动仍会断;
- **锁屏态自动解锁**(Autologon + 注册表):凭据落盘,安全不可接受。
  已知边界:若会话被策略强制锁屏且 tscon 无法恢复,当前方案只能告警。

## 后果

- 用户断开 RDP → 5 秒内巡检自动挂回物理控制台(息屏)→ 合成输入/截图/OCR
  全部恢复 → 发送照常;
- RDP 最小化(未断开)不再造成永久卡死——90s 后自愈;
- 验证:断开后探针观察自愈时序 + 发送一条测试消息核对消息库 `success`。
