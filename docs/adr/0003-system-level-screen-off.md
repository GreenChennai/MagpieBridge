# ADR-0003: 息屏方案 = 系统级息屏 + 保黑看门狗 + 物理输入吞没

日期:2026-09-07
状态:已接受

## 背景

7x24 挂机时显示器常亮费电刺眼,但直接"关显示器电源/拔线"会让 Windows
认为显示器消失,微信(Qt)窗口重排甚至锁死,合成输入全部失效。
用户提出两条路:黑色遮罩窗口盖屏,或系统级息屏。

## 决策

**系统级息屏**(`SC_MONITORPOWER=2` 广播)为主方案:

- 只关背光,不改变显示拓扑 → 微信窗口坐标不重排,自动化照常;
- GPU/渲染管线继续跑 → 截图(屏幕 BitBlt)仍有效;
- 配套三层防护:
  1. **保黑看门狗**:被物理输入意外唤醒时,6s 内重新压黑;
  2. **物理输入吞没**:息屏期间挂低级键鼠钩子,吞掉人类的鼠标/键盘事件
     (除 ESC 与息屏快捷键),防止误碰唤醒/误操作;
     带 `LLKHF_INJECTED` 的合成事件(宿主自己的自动化)全部放行;
  3. **全局快捷键**:`Ctrl+Alt+O` 开/关息屏,`ESC` 亮屏;
     显示器关了看不见时,一切操作走快捷键。

**否决黑色遮罩窗口**:置顶黑窗有 z-order 干扰自动化点击的风险
(微信被 `restore_and_focus` 置前时会盖过/触发层级竞争),
且遮罩不省电、不防误碰;系统级息屏无此风险。
遮罩仅作为 `screen_off.mode: "overlay"` 保留为 fallback,不默认启用。

## 前置条件

- 进程必须以管理员运行(已有自动提权);BlockInput/钩子/tscon 均需要。
- 息屏状态用模块级标志 + 看门狗线程维护(修复旧版缺 `global` 导致
  状态永远 False、保黑线程秒退、ESC 唤醒失效的 bug)。

## 后果

- 息屏期间人无法用键鼠(除 ESC),这是**特性**而不是缺陷:机器完全交给宿主。
- `tools/screen_off.py` 提供独立 CLI(off/on/status/toggle),可脱离宿主使用。
