# 邮件提醒（SMTP 告警）使用说明

> 当微信消息发送失败 / 触发风控 / 出现意外异常导致消息无法发出时，
> 自动通过 SMTP 发送告警邮件，提醒需要人工接管。

## 一、功能概述

- **触发时机**：所有发送路径失败或异常时触发——
  Web 后台发送、OneBot HTTP/WS 发送、插件转发（如 LeadsLinker）、
  管理员指令发送、监听器自动回复。
- **不写死授权码**：SMTP 配置（含授权码）保存在 `config.json` 的 `alert` 段，
  由使用者在后台自行填写，代码里不包含任何账号密码。
- **防刷屏**：默认 300 秒冷却期，冷却期内重复失败只发一封，
  并把期间累计的失败次数合并进下一封邮件正文。

## 二、配置步骤（QQ 邮箱为例）

1. 打开管理后台 `http://127.0.0.1:8080`，进入「设置」。
2. 找到「邮件提醒」标签页（设置页顶部有 OneBot 配置 / 微信配置 / 管理员配置 / 邮件提醒 四个页签），打开「启用邮件提醒」开关。
3. 填写以下字段：

   | 字段 | 值（QQ 邮箱） | 说明 |
   |------|--------------|------|
   | SMTP 服务器 | `smtp.qq.com` | 发送服务器 |
   | 端口 | `465` | 465=SSL；或 587=STARTTLS |
   | SSL 加密 | 勾选 | 465 必须勾选 |
   | 发件邮箱 | `xxx@qq.com` | 完整邮箱地址 = SMTP 登录账号 |
   | 授权码 | `xxxxxxxxxxxxxxxx` | **授权码，不是 QQ 登录密码** |
   | 收件邮箱 | `alert@qq.com` | 告警邮件发往哪里 |
   | 冷却时间 | `300` | 秒；0 = 每次失败都发 |

4. 点击「发送测试邮件」验证配置是否可用（会向收件邮箱发一封测试邮件）。
5. 点击「保存配置」。

> ⚠️ **四项必填：SMTP 服务器、发件邮箱、授权码、收件邮箱**（界面上带红色星号）。
> 只填授权码和收件邮箱是不够的——**发件邮箱就是 SMTP 登录账号**（QQ 邮箱填完整地址如 `123456@qq.com`），
> 缺任何一项都会提示「请先填写：xxx」并列出具体缺哪个字段。
> 测试邮件在开关未打开时也能发送，方便先验证配置、再决定是否启用。

### 授权码怎么获取

QQ 邮箱网页版 → 设置 → 账号 → 「POP3/IMAP/SMTP/Exchange/CardDAV/CalDAV 服务」
→ 开启 SMTP 服务 → 按提示生成授权码。

> 授权码是 QQ 邮箱用于登录第三方客户端/服务的专用密码，不要告诉他人；
> 更改 QQ 账号密码会使授权码失效，需重新生成。

## 三、授权码安全

- 后台 `/api/config` 返回的授权码为**打码值**（`****后4位`），不会明文回显。
- 保存时授权码**留空**或传回打码值 → **保留原值**（不覆盖）。
- 只有填写新的完整授权码才会更新。
- 配置保存在本地 `config.json`，请勿将 `config.json` 分享给他人。

## 四、触发与冷却机制

```
发送失败/异常 → UIEngine 收口 → alerter.notify_send_failure()
    ├─ 未启用/未配置 → 静默跳过（不打扰）
    ├─ 冷却期内     → 累计失败数，不重复发信
    └─ 正常         → 发送告警邮件（正文含类型/目标/详情/排查建议）
```

- 冷却期内累计的失败会在下一次真正发送时合并进正文：
  `（冷却期内另有 N 次失败已合并，不再单独发信）`
- 邮件发送本身失败不会影响主流程（只记日志），且会释放冷却窗口，
  避免后续告警被永久吞掉。

## 五、config.json 配置项

```json
{
  "alert": {
    "enabled": false,
    "smtp_host": "smtp.qq.com",
    "smtp_port": 465,
    "use_ssl": true,
    "smtp_user": "",
    "auth_code": "",
    "receiver": "",
    "subject_prefix": "[MagpieBridge]",
    "cooldown_sec": 300
  }
}
```

| 配置项 | 说明 | 默认 |
|--------|------|------|
| `enabled` | 总开关 | false |
| `smtp_host` | SMTP 服务器 | smtp.qq.com |
| `smtp_port` | 端口（465 SSL / 587 STARTTLS / 25） | 465 |
| `use_ssl` | 是否 SSL | true |
| `smtp_user` | 登录账号 = 完整邮箱 | "" |
| `auth_code` | 授权码 | "" |
| `receiver` | 收件邮箱 | "" |
| `subject_prefix` | 邮件主题前缀 | [MagpieBridge] |
| `cooldown_sec` | 冷却秒数（0=不冷却） | 300 |

> 后台修改配置会**热生效**（无需重启），并同步写入 `config.json`。

## 六、支持的其他邮箱

任何支持 SMTP 的邮箱均可（163/Gmail/Outlook 等），只需按对应服务商的
SMTP 地址、端口与加密方式填写：

| 服务商 | SMTP 服务器 | 端口 |
|--------|------------|------|
| QQ 邮箱 | smtp.qq.com | 465/587 |
| 163 邮箱 | smtp.163.com | 465/994 |
| Gmail | smtp.gmail.com | 465/587（需应用专用密码） |
| Outlook | smtp.office365.com | 587 |

## 七、常见错误与排查

「发送测试邮件」失败时会直接返回**具体原因**（不会再误报成功），按下表对照处理：

| 提示信息 | 原因 | 处理 |
|---------|------|------|
| 请先填写：发件邮箱 | 必填项未填（会逐项列出具体缺哪个） | 补齐对应字段后重试 |
| `535 授权码错误或未开启 SMTP 服务` | ①填的是 QQ 登录密码而非授权码 ②QQ 邮箱未开启 SMTP 服务 ③授权码已过期（改过 QQ 密码会失效） | QQ 邮箱 → 设置 → 账号 → 开启 IMAP/SMTP 服务 → 重新生成授权码 |
| 服务器主动断开连接（端口与「使用 SSL」不匹配） | 465 与 SSL 搭配错误 | **465 → 勾选 SSL；587 → 不勾选 SSL**（走 STARTTLS） |
| 无法连接 SMTP 服务器 / 连接超时 | 地址写错、端口被防火墙或运营商拦截 | 核对地址与端口；临时关闭防火墙/杀软重试；改试 587 端口 |
| 网络错误 | DNS 解析失败或端口不通 | 检查网络连通性 |
| 发件邮箱被服务器拒绝 | 发件地址无效或与登录账号不一致 | 发件邮箱必须填**登录用的完整邮箱地址** |
| 收件邮箱被服务器拒绝 | 收件地址无效 | 检查收件邮箱是否写错 |

### 仍收不到邮件？

1. 先确认测试邮件提示的是「已发送」而非失败（失败会明确给出原因）。
2. 提示已发送但收不到 → 检查垃圾邮件/广告邮件箱；把发件地址加入白名单。
3. 确认「启用邮件提醒」开关已打开——未打开时测试能发，但实际发送失败**不会**自动告警
   （此时测试成功的提示里会附带这行提醒）。
4. 查看运行日志 `logs/magpie.log`，搜索 `邮件告警` / `SMTP` 关键字。
